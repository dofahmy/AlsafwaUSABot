# راجح — بوت العملاء (بدون شراء داخل تليجرام)

## الوظائف المنفذة
- /start وقائمة «طلب تفعيل تجربة»، «طلب تفعيل اشتراك»، «توصياتي»، «حسابي».
- طلبات تفعيل وموافقة/رفض من حسابات المدراء داخل تليجرام.
- التفعيل اليدوي للاشتراك يعني أن المدير تأكد من الدفع خارج تليجرام؛ لا توجد أي بوابة دفع أو إدخال بطاقات داخل البوت.
- قاعدة بيانات للعملاء والطلبات والإشارات وسجل الرسائل. PostgreSQL للإنتاج.
- API للأحداث من المونيتور المحلي مع مفتاح سري، وإرسال خاص للأعضاء المفعّلين، والربط بين الإشارات وتحديثاتها.
- API داخلي للتأكيد التلقائي بعد تحقق جهة دفع خارجية موثوقة من نجاح العملية، مع منع تكرار معالجة نفس معرف الدفع.

## التشغيل على Railway
أنشئي مشروعًا أو خدمتين جديدتين داخل مشروع مستقل عن راجح القديم، بنفس مصدر هذا المجلد:
1. Web API: `uvicorn api:app --host 0.0.0.0 --port $PORT`
2. Telegram worker: `python bot.py`
اربطي الاثنين بنفس PostgreSQL عبر DATABASE_URL، ولا تستخدمي SQLite في إنتاج موزع.
المتغيرات:
- `DATABASE_URL` رابط قاعدة البيانات.
- `CUSTOMER_BOT_TOKEN` توكن بوت *جديد* من BotFather (لا تشاركيه).
- `ADMIN_TELEGRAM_IDS` معرفات تليجرام الرقمية للإدارة، مفصولة بفواصل.
- `BRIDGE_SECRET` قيمة عشوائية قوية مشتركة بين المونيتور والـ API.
- `PAYMENT_BRIDGE_SECRET` قيمة سرية مختلفة لا تُشارك مع العملاء أو المونيتور.
- `TRIAL_DAYS=3` عدد أيام التجربة.
- `MANUAL_SUBSCRIPTION_DAYS=30` عدد أيام الاشتراك المعتمد يدويًا.

## تشغيل المونيتور عندك
انقلي `bridge.py` إلى مجلد المونيتور.
في `nokhba_live2.py` أضيفي `from bridge import emit` ثم في `open_signal` بعد `tr['msg_id'] = tg_send(text)` أضيفي:
`emit(tr, 'open', text)`.
في كل موضع رسالة هدف أو وقف أو قفل، يفضل إنشاء نص في متغير ثم استدعاء `tg_send(msg, ...)` و `emit(tr, kind, msg)`؛ أو استخدمي `nokhba_live2_integrated.py` المرفق بعد اختبار نسخة احتياطية.
متغيرات المونيتور المحلي:
- `RAJIH_BRIDGE_URL=https://<your-new-api>.up.railway.app`
- `RAJIH_BRIDGE_KEY=<same-BRIDGE_SECRET>`
احتفظي بملفات الحالة المحلية والنسخة الأصلية؛ انقطاع الـ API لن يوقف إشارات القناة لكنه قد يمنع وصول الإشارات الخاصة. مطلوب لاحقًا إضافة outbox محلي دائم لضمان إعادة إرسال كل الأحداث.

## تفعيل دفع البطاقات الخارجي آليًا
لا يمكن تفعيل الاستقبال الفعلي بدون حساب تاجر معتمد لدى مزود الدفع. الموقع الخارجي هو الذي ينشئ صفحة الدفع ويربط الطلب بـ Telegram ID، ثم يتحقق من webhook وتوقيعه والمبلغ والعملة وحالة الدفع من المزود **على الخادم** قبل أن يستدعي `/internal/confirmed-payment` مع الهيدر `X-Payment-Bridge-Key`.
مثال JSON من خدمة الدفع الموثوقة فقط:
`{"provider":"approved_gateway","provider_payment_id":"unique_processed_charge_id","telegram_id":123456789,"period_days":30}`
لا تقبلي هذا الطلب من المتصفح أو العميل. لا تستعملي المعرف الوارد من العميل كدليل على الدفع.

## ملاحظات أمنية/تشغيلية
- هذا تنفيذ أولي قابل للاختبار، وليس إطلاقًا تجاريًا نهائيًا.
- خاصية التوصيل الحالية قد تعيد رسالة عند تعطل الشبكة بعد نجاح طلب Telegram؛ حسّني احتفاظ Message ID وإعادة المحاولة قبل الإنتاج.
- لا توجد صفحة دفع بالبطاقات ضمن الحزمة لأن بيانات المزود والأسعار لم تُحدد.
- لإرسال تنبيهات تليجرام للمشترك يجب أن يبدأ العميل محادثة مع البوت أولًا.
- اشتراك العميل يبدأ من تاريخ الموافقة؛ إعادة الاشتراك تمدد من آخر تاريخ صالح.
- اختبري سياسات الاستخدام والترخيص لبيانات السوق قبل التوزيع المدفوع.
